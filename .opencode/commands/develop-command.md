Target: $ARGUMENTS. Jalankan mode DEVELOPMENT dari skill `backlog-workflow` (load via skill tool) + ladder `ponytail`. Tampilkan checklist ini di awal dan update statusnya tiap step selesai:

> **Kapan pakai command ini:** hanya untuk refactor kecil yang muat dalam 1 sesi (Step 2 & Step 4 tidak butuh ganti sesi).
> Untuk pekerjaan panjang, cross-session, atau yang butuh gate user di tengah → pakai `/develop-plan "<target>"` (Step 1-4, tulis saved plan) lalu `/develop-code "<target>"` (Step 5-7). Keduanya menulis format saved plan yang sama: `.opencode/plans/<slug>.md` (lihat `/develop-plan` § "Saved plan — format wajib").

- [ ] Step 1 (plan): analisis kebutuhan refactor dari dokumentasi → update doc DAHULU (kode belum disentuh). Exit: doc yang relevan stating apa berubah/kenapa/apa tidak berubah. **Doc target repo ini = file markdown top-level**: `ARCHITECTURE.md` (arsitektur), `APPLY-LAYER.md` (apply layer), `OPERATOR-PLAYBOOK.md` (operator flow), `README.md` (public-facing), `CHANGELOG.md` (riwayat). Untuk logika di dalam skill: `skills/<skill>/SKILL.md`; untuk referensi analitik: `google-ads/references/<topik>-playbook.md`. Exit: doc ADA dan menyatakan scope refactor.
- [ ] Step 2 (plan + DECISION GATE): cek dulu exit Step 1 lolos (doc ter-update, kode belum disentuh) — belum → selesaikan Step 1. Lalu ponytail review (load skill `ponytail` via skill tool) → tulis hasil (apa dipangkas + alasan 1 baris) di doc. Jika rencana menyentuh fitur, scenario UI, atau kontrak data (mis. field manifest apply, format draft, query GAQL, atau file di `evals/`) → STOP, pakai `question` tool minta konfirmasi user. Exit: scope final terkunci di doc. Lanjut hanya setelah user jawab; jawaban tercatat di doc.
- [ ] Step 3 (plan): analisis pre-requisite test regresi → tulis bagian "Test Regresi" di doc (area terdampak, test existing pelindung, test minimal tambahan). WAJIB baca `evals/` dulu dengan urutan: grep `evals/*.json` (case id + expected) untuk tahu perilaku sudah tercover (jangan tulis baru) → baca `evals/run.py` untuk tahu harness eksekusinya → baru pilih layer + budget. **Layer test repo ini (murah → mahal)**: (1) `evals/cases.json` — intent classification, kategori input → expected output; (2) `evals/decision_cases.json` — keputusan tracking/budget/structure; (3) `evals/apply_cases.json` — parsing manifest + guardrail apply; (4) `evals/fixtures/` — fixture input nyata; (5) `evals/test-shell-regressions.sh` — regresi shell (retrieval ladder, negative inventory). **Perilaku sengaja tidak dites** → baris `Sengaja tidak dites` + pemicu `add when`. Exit: bagian ADA di doc.
- [ ] Step 4 (plan + DECISION GATE): cek dulu exit Step 3 lolos (bagian "Test Regresi" ADA di doc) — belum → selesaikan Step 3. Lalu ponytail review test → klasifikasi kandidat coret (redundansi lintas layer, overkill layer, copy implementasi, fixture besar, fragmentasi file) + alasan di doc. Kalau ada kandidat coret yang berarti HAPUS/edit test existing → DECISION GATE WAJIB, STOP via `question` (agent tidak boleh menyentuh file test tanpa persetujuan eksplisit); kalau tidak ada kandidat hapus, gate tidak wajib. Exit: daftar test final terkunci **di doc**.
- [ ] Close-out (saved plan): setelah exit Step 4 lolos → tulis `.opencode/plans/<slug>.md` (`status: planning-done`, Scope Terkunci, Test Regresi Terkunci, lampiran sesi — format wajib di `/develop-plan` § "Saved plan — format wajib") supaya bisa di-resume `/develop-code`. Exit: plan + lampiran ADA.
- [ ] Step 5 (build): implement test pre-requisite sesuai daftar terkunci → harus PASS (jangan asumsi). Eksekusi: `python3 evals/run.py` (semua case: intent + decision + parser + apply) → `bash evals/test-shell-regressions.sh` (regresi shell). **Jangan full suite tiap iterasi** — kalau area spesifik, jalankan runner yang sama tapi filter kalau runner mendukung; kalau tidak, `python3 evals/run.py` sudah cukup cepat (7+ case, <1 detik). Terlarang tanpa izin: ubah source produksi demi test hijau, longgarkan assertion, hapus/`skip` test existing. Exit: test ADA dan PASS, tanpa test di luar daftar.
- [ ] Step 6 (build): implement kode → syntax check clean: `python3 -m compileall -q scripts/ evals/` (untuk .py) dan `bash -n <file.sh>` (untuk shell). Exit: kode jadi + syntax clean.
- [ ] Step 7 (build): ponytail review akhir (load skill `ponytail`) atas kode Step 6 + scope terkunci Step 2/4 → tulis hasil review ke doc (bukan hanya di chat), lalu sederhanakan doc: tambah wireframe sebelum/sesudah kalau relevan, HAPUS bagian duplikat/kadaluarsa, update `CHANGELOG.md`. Exit: hasil review tertulis di doc + doc ramping + changelog updated.

Close-out akhir: update `.opencode/plans/<slug>.md` → `status: done`, centang Step 5-7, tautkan commit/PR. Lalu `git rm .opencode/plans/<slug>.session.json` (bila ada) — lampiran sudah tidak perlu: ringkasan final permanen di plan + `.megamemory/knowledge.db`.

Aturan: 1-2 baris laporan per step (step apa, artifact apa). Step tanpa exit artifact = belum selesai, tidak boleh lanjut. Ringkasan akhir maks 3 baris.
